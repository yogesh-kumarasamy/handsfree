# Trackers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A project picks Jira (default), GitHub Issues or Linear as its tracker; tickets are searched, commented and moved to "done" on merge through a `TrackerAdapter`; Linear signs in via OAuth with dynamic client registration; prompts and UI copy become tracker-neutral.

**Architecture:** `engine/src/trackers/` holds the adapter interface and three implementations (Jira = today's `acli` code moved; GitHub = `gh issue …`; Linear = the messaging MCP client against `mcp.linear.app` with tool-schema-driven argument names). The loopback OAuth login inside `MessagingService` is extracted into `engine/src/oauthlogin.ts` (`LoopbackLogin`) so both Setmore and Linear use it; Linear adds dynamic registration. The orchestrator calls the adapter at pick-up, PR-open comment and merge. `ProjectConfig.tracker` replaces the three Jira fields with migration.

**Tech Stack:** Node 20, TypeScript/esbuild, `node --test`, React 18, `acli`, `gh`, existing fakes (`engine/test/fakes/`), existing e2e harness.

**Spec:** `docs/superpowers/specs/2026-10-15-trackers-design.md` (messaging spec for the reused OAuth/MCP pieces: `docs/superpowers/specs/2026-10-15-messaging-design.md`)

## Global Constraints

- No new runtime dependencies.
- The three Jira fields (`jql`, `jiraSearchCommand`, `jiraCommentCommand`) are removed from `ProjectConfig`; `normalizeProject` migrates them into `tracker` (kind `jira`, `doneStatus: "Done"`).
- Ticket keys: Jira `ABC-123`; GitHub `<repo-name>#<number>`; Linear `identifier`.
- Tokens: `DATA_DIR/auth/linear.json` (0600) and the registered client in `DATA_DIR/auth/linear-client.json`; `AccountStatus` only on SSE/state.
- Transition failures never block merge handling (logged + notified).
- Copy: no "Jira" in generic UI/prompts; use `TRACKER_NOUN[kind]`.
- **Parallel work notice:** another branch (`worktree-routines`) is being built at the same time. It appends to `types.ts` (RoutineConfig…), `store.ts` (normalizeRoutine), `orchestrator.ts` (a `routines` field + 3 one-line hooks), `server.ts` (2 routes), `src/api.ts`, `src/mock.ts`, `src/views/Projects.tsx` (a "Routines" step before Review), `src/views/Dashboard.tsx` (a card after the sections), `messaging/service.ts` (one appended method). This branch owns: everything tracker/OAuth-login related, the Projects "Tracker" step (index 1), Settings Accounts, dashboard/sidebar copy. When you edit a shared file, add/replace only your own lines; don't reorder or reformat the file.
- `npm run typecheck` and `npm run test:engine` pass after every task. Commit after every task with the repo's short imperative style.

## Review Focus

1. **GitHub remote URL shapes** — `git@github.com:owner/repo.git`, `https://github.com/owner/repo`, `ssh://git@github.com/owner/repo.git`, and a non-GitHub remote (must error with "Set the GitHub repo"). Pinned by the `github` unit test in Task 3.
2. **A Jira done status with spaces or quotes** (`"In Review"`, `Won't Do`) must be shell-quoted correctly in the transition command. Pinned by the `jira` unit test in Task 3.
3. **Linear tool argument names differ from the spec's guess** — the adapter must read `tools/list` schemas and fall back (`issueId|id|issue`, `state|stateId|status`); a missing tool makes `comment`/`transition` `skipped`, never a crash. Pinned by the Linear unit tests in Task 3 (two schema variants).
4. **Migration of a saved config** with the old Jira fields and no `tracker` must produce a working Jira project (query, custom commands preserved, `doneStatus` "Done"). Pinned by the store unit test in Task 1.
5. **Linear login when the redirect port changes** after registration — the stored client's redirect URI no longer matches; the login must re-register instead of failing with `invalid_redirect_uri`. Pinned by the `oauthlogin` unit test in Task 2.

export function normalizeTracker(p: Partial<ProjectConfig> & { jql?: string; jiraSearchCommand?: string; jiraCommentCommand?: string }): TrackerConfig {
  const t = p.tracker as Partial<TrackerConfig> | undefined;
  const kind: TrackerKind = t?.kind === "github" || t?.kind === "linear" ? t.kind : "jira";
  if (!t) {
    // 0.1 config: Jira only.
    return { kind: "jira", query: p.jql || "", searchCommand: p.jiraSearchCommand ?? "", commentCommand: p.jiraCommentCommand ?? "", transitionCommand: "", doneStatus: "Done", repo: "", linearAssignee: "me" };
  }
  return {
    kind,
    query: t.query || "",
    searchCommand: t.searchCommand ?? "",
    commentCommand: t.commentCommand ?? "",
    transitionCommand: t.transitionCommand ?? "",
    doneStatus: t.doneStatus ?? DEFAULT_DONE_STATUS[kind],
    repo: t.repo || "",
    linearAssignee: t.linearAssignee ?? "me",
  };
}
